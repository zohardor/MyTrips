# הטיולים שלי

אתר לתכנון טיולים: תקציב, המרת מטבע, מזג אוויר ממוצע, אטרקציות, תוכנית יומית, יומן עם תמונות ושיתוף עם שותפים לטיול.

האתר עצמו סטטי ומתארח ב-GitHub Pages. ההרשמה, הנתונים והתמונות נשמרים ב-Supabase.

## מבנה הקבצים

| קובץ | תפקיד |
|---|---|
| `index.html` | האפליקציה: רשימת הטיולים והתכנון עצמו |
| `login.html` | כניסה, הרשמה ואיפוס סיסמה |
| `view.html` | הדף הציבורי של טיול, לצפייה בלי הרשמה |
| `config.js` | כתובת הפרויקט ב-Supabase ומפתח ה-anon |
| `route.js` | מיקומי שדות התעופה ומפת המסלול, משותפים לשני העמודים |
| `supabase/schema.sql` | הטבלאות, הרשאות ה-RLS, השיתוף, אחסון התמונות והרשאת מנהל |
| `supabase/make-admin.sql` | הגדרת משתמש כמנהל עם גישה מלאה |
| `.nojekyll` | מונע מ-GitHub Pages לעבד את הקבצים |

## שלב 1: הקמת Supabase

1. ב-[supabase.com](https://supabase.com) יוצרים פרויקט חדש. מומלץ לבחור אזור באירופה (למשל Frankfurt) כדי שהאתר יגיב מהר מישראל.
2. נכנסים ל-**SQL Editor**, פותחים שאילתה חדשה, מדביקים את כל התוכן של `supabase/schema.sql` ולוחצים **Run**. הסקריפט יוצר:
   - הטבלאות `profiles`, `trips`, `trip_members` ו-`journal_entries`.
   - מדיניות RLS, כך שכל משתמש רואה רק את הטיולים שלו ואת אלה ששותפו איתו.
   - את הפונקציה `share_trip` לשיתוף לפי מייל.
   - bucket פרטי בשם `trip-photos` לתמונות היומן, עם הרשאות לפי הטיול.
   - הפעלת Realtime על הטבלאות, כדי ששינויים יופיעו אצל כל המשתתפים בזמן אמת.

   מותר להריץ את הסקריפט שוב, למשל אחרי עדכון. הוא לא מוחק נתונים.

3. ב-**Project Settings → API** מעתיקים את **Project URL** ואת המפתח **anon public**.

## שלב 2: חיבור הקוד

פותחים את `config.js` וממלאים את שני הערכים:

```js
window.TRIP_CONFIG = {
  SUPABASE_URL: 'https://abcdefgh.supabase.co',
  SUPABASE_ANON_KEY: 'eyJhbGciOi...',
  ENABLE_GOOGLE: false
};
```

מפתח ה-anon מיועד לדפדפן, ומותר שיהיה גלוי במאגר ציבורי. מה שמגן על הנתונים הוא מדיניות ה-RLS. **לעולם לא** לשים בקוד את מפתח ה-`service_role`.

## שלב 3: העלאה ל-GitHub Pages

1. יוצרים מאגר חדש ב-GitHub, למשל `my-trips`.
2. מעלים אליו את כל הקבצים, כולל `.nojekyll` ותיקיית `supabase`:
   ```bash
   git init
   git add .
   git commit -m "Trip planner"
   git branch -M main
   git remote add origin https://github.com/USERNAME/my-trips.git
   git push -u origin main
   ```
3. במאגר: **Settings → Pages → Build and deployment**. בוחרים **Deploy from a branch**, ענף `main`, תיקייה `/ (root)`, ושומרים.
4. אחרי דקה או שתיים האתר זמין בכתובת `https://USERNAME.github.io/my-trips/`.

## שלב 4: הגדרת כתובות האתר ב-Supabase

בלי השלב הזה, קישורי אימות המייל ואיפוס הסיסמה לא יחזירו לאתר.

ב-**Authentication → URL Configuration**:

- **Site URL:** `https://USERNAME.github.io/my-trips/`
- **Redirect URLs:** מוסיפים את שתי הכתובות:
  - `https://USERNAME.github.io/my-trips/index.html`
  - `https://USERNAME.github.io/my-trips/login.html`

  לבדיקות מקומיות אפשר להוסיף גם `http://localhost:8000/**`.

## שלב 5 (לא חובה): התאמות

- **אימות מייל:** כברירת מחדל Supabase שולח מייל אישור בהרשמה. אפשר לכבות את זה ב-**Authentication → Providers → Email → Confirm email**, אבל עדיף להשאיר את האימות פעיל.
- **מיילים בעברית:** ב-**Authentication → Email Templates** אפשר לתרגם את נוסחי המיילים (אישור הרשמה, איפוס סיסמה).
- **שליחת מיילים:** שירות המייל המובנה של Supabase מוגבל לכמה מיילים בשעה ומיועד לבדיקות. לשימוש אמיתי מגדירים SMTP משלכם ב-**Project Settings → Authentication → SMTP Settings**, למשל Resend, Brevo או SendGrid.
- **כניסה עם Google:** מפעילים את הספק ב-**Authentication → Providers → Google** לפי ההוראות שם, ואז משנים ב-`config.js` את `ENABLE_GOOGLE` ל-`true`.

## משתמש מנהל

מנהל רואה את כל הטיולים של כל המשתמשים, יכול לערוך, לשתף ולמחוק כל טיול, יכול לכתוב ולמחוק בכל יומן ולראות את כל התמונות. במסך הבית יש לו גם טבלה של כל המשתמשים הרשומים, עם תאריך ההרשמה, הכניסה האחרונה ומספר הטיולים והרשומות של כל אחד.

**הגדרת מנהל:**
1. נרשמים לאתר עם המייל של המנהל ומאשרים את המייל. אפשר גם ליצור את המשתמש ב-**Authentication → Users → Add user** ולסמן **Auto Confirm User**.
2. פותחים את `supabase/make-admin.sql`, מחליפים את `admin@example.com` במייל של המנהל, ומריצים ב-SQL Editor.
3. המנהל נכנס מחדש לאתר. ליד השם שלו יופיע "(מנהל)".

הרשאת המנהל נשמרת בטבלה `admins`, שאין אליה גישה מהדפדפן. לכן אפשר לתת או להסיר הרשאת מנהל רק מתוך Supabase. להסרה יש שורה מוכנה בסוף `make-admin.sql`.

**לפרויקט שכבר מותקן:** מריצים שוב את `schema.sql` המעודכן. הסקריפט מוסיף את התמיכה במנהל בלי לפגוע בנתונים הקיימים.

## איך השיתוף עובד

- מי שיוצר טיול הוא **מארגן הטיול**. רק הוא יכול לשתף את הטיול, להסיר משתתפים ולמחוק אותו.
- משתפים דרך הכפתור **שיתוף** בתוך הטיול, לפי כתובת המייל. המשתתף צריך להירשם לאתר קודם.
- יש שתי רמות הרשאה:
  - **עריכה:** משנים את התכנון וכותבים ביומן.
  - **צפייה:** רק רואים את התכנון ואת היומן.
- משתתף יכול לעזוב טיול בכל רגע, דרך הכפתור **משתתפים**.
- **שכפול** טיול יוצר עותק פרטי שלכם, בלי היומן. זה עובד גם על טיול ששותף איתכם.

## טיול פומבי

מארגן הטיול (או מנהל) יכול להפוך טיול לפומבי מחלון **שיתוף**. אחרי זה, כל מי שמקבל את הקישור יכול לצפות בטיול בלי להירשם. הקישור נראה כך: `.../view.html?trip=<מזהה>`.

- **מה רואים בדף הציבורי:** תמיד את היעד, התאריכים, מספר הנוסעים, מפת המסלול והתוכנית היומית. היומן והתמונות, וגם התקציב, מופיעים רק אם המארגן סימן אותם.
- **אבטחה:** הדף הציבורי מקבל את הנתונים דרך הפונקציה `get_public_trip`, שמחזירה רק את מה שאושר. כשהתקציב לא משותף, הסכומים לא נשלחים לדפדפן בכלל. הצ׳קליסט והמיילים של המשתתפים לא נשלחים אף פעם.
- **מי יכול לשנות:** רק המארגן או מנהל. משתתף עם הרשאת עריכה לא יכול להפוך טיול לפומבי, וגם זה נאכף בשרת.
- **ביטול:** מבטלים את הסימון "טיול פומבי", והקישור מפסיק לעבוד מיד.
- **מנועי חיפוש:** הדף מסומן כ-`noindex`, כך שמנועי חיפוש לא אמורים לאנדקס אותו. עדיין, כל מי שמקבל את הקישור יכול להעביר אותו הלאה.

## בדיקה מקומית

```bash
python3 -m http.server 8000
```

ואז פותחים את `http://localhost:8000/login.html`. לא לפתוח את הקבצים ישירות מהדיסק (`file://`), כי ההתחברות לא תעבוד כך.

## הערות

- **הנתונים לא עוברים אוטומטית מהגרסה שהייתה ב-claude.ai.** זה אחסון נפרד, ולכן את הטיולים משם צריך ליצור מחדש באתר.
- **גודל התמונות:** התמונות מוקטנות בדפדפן לפני ההעלאה, ל-1800 פיקסלים בצד הארוך, בפורמט JPG. בתוכנית החינמית של Supabase יש 1GB אחסון, שמספיקים לאלפי תמונות.
- **הודעה בשיתוף:** כשמשתפים עם מייל שלא רשום, האתר אומר שהמשתמש לא נמצא. כלומר, מארגן טיול יכול לדעת אם מייל מסוים רשום לאתר. באתר פרטי למשפחה ולחברים זה סביר.
- **השהיית פרויקט:** פרויקט חינמי ב-Supabase מושהה אחרי שבוע בלי פעילות. מפעילים אותו מחדש בלחיצה בלוח הבקרה.
